BUSINESS KNOWLEDGE ENGINE

Business Knowledge 怎么用 AI 自动生成？

目标不是让 AI “编业务规则”，而是让 AI 从代码、CodeGraph、需求文档、测试、Git/PR 等真实证据中挖掘候选知识，再经过证据绑定与人工确认，形成可持续维护的企业业务知识资产。

核心原则
AI 负责“发现、整理、关联、提出候选”；人负责“确认业务事实”。
核心闭环
Evidence → Candidate → Review → Confirmed → Reuse

01 · 业务知识不是一堆文档

要形成结构化、可证据追溯的知识对象
BusinessTerm
订单、支付成功、取消、结算等概念及别名
BusinessRule
在什么条件下必须、允许、禁止做什么
BusinessFlow
正常/异常流程、角色、跨模块行为
State / Invariant
状态转换以及不能被破坏的业务约束

02 · AI 从哪里“挖”业务知识

多源证据比单一文档可靠
CodeGraph结构 / 调用 / 影响
+
业务文档需求 / 产品 / 设计
+
测试可执行行为证据
+
Git / PR历史原因
+
Spec / ADR已确认设计
→
Knowledge Agent抽取候选知识

代码事实

例如：取消订单会调用库存释放，并发布 OrderCancelledEvent。

行为证据

测试证明20分钟未支付会进入CANCELLED，而已支付订单不会。

历史证据

Git/PR 可以解释为什么某个业务规则长期这样设计，避免只看当前代码。

03 · Knowledge Agent 实际执行什么

不是一次“总结”，而是一个证据驱动的抽取流程
Step 1 · 任务识别
识别领域Order / Payment / Refund…
识别对象Term / Rule / Flow / State
定义检索范围CodeGraph + Docs + Tests + Git
Step 2 · Evidence Retrieval
CodeGraph相关符号/调用/影响/测试
全文/语义检索业务文档/历史需求
Git / PR历史变化与设计原因
Step 3 · Reasoning
DeepSeek V4聚合证据 → 提炼候选业务知识

04 · 候选知识必须带证据

每条知识都要能回答“你为什么这么认为？”
type: BusinessRule
rule: "普通订单30分钟未支付自动取消"
status: CANDIDATE
confidence: HIGH

evidence:
- requirements/order-timeout.md
- OrderTimeoutJob.java:120
- OrderTimeoutTest.java:85
- PR #1234

related_symbols:
- OrderTimeoutJob
- OrderService.cancel
- OrderStatus.CANCELLED

05 · 三态知识治理

避免 AI 把推测污染成组织知识

UNKNOWN

资料不足、存在冲突或AI无法确认。

CANDIDATE

AI根据证据发现的候选规则，等待人工确认。

CONFIRMED

业务人员或权威依据确认后的正式知识，可以被后续任务直接复用。

关键规则：没有足够证据时，不允许 Agent 自行把 UNKNOWN 提升为 CONFIRMED。

06 · AI 自动提取 vs 人工确认

把人的时间花在“业务判断”，而不是“整理资料”
环节AI人工
资料搜集自动查询 CodeGraph、文档、测试、Git、Spec定义权威来源
知识抽取自动识别 Term / Rule / Flow / State / Invariant抽查
证据绑定自动记录文件、符号、测试、PR等 evidence确认是否足够
冲突检测发现代码/文档/测试不一致裁定真实业务含义
知识发布生成 Candidate / Update Proposal确认后进入正式知识库

07 · 知识存在哪里

正式知识和 AI 工作记忆分开

正式 Business Knowledge

.ai/ 或统一知识库，Git 管理，可Review，可回滚。适合稳定业务规则、流程、术语、状态机和ADR。

AI Memory

CodeGraph/Agent 的持久记忆，用于工作上下文、排障经验、已知问题和临时发现。重要事实经过确认后再“晋升”为正式知识。

08 · 最终形成知识飞轮

每做一次真实变更，下一次就更懂系统
真实需求产生新信息
→
AI分析发现候选规则
→
人工确认形成事实
→
Business KB可复用
→
下一次任务上下文更完整
汇报结论：业务知识不是让人手工整理成一大堆文档，而是由 AI 从真实证据中持续“挖掘 + 绑定证据 + 提出候选”，再由人完成业务事实确认，最终形成可检索、可Review、可持续更新的企业知识资产。
